# UaCodes

Мала бібліотека .NET без залежностей, яка перевіряє українські коди: ЄДРПОУ, РНОКПП, IBAN, EIC і КАТОТТГ. Вона рахує контрольні розряди, приводить коди до одного вигляду і дістає з них те, що закладено у форматі: код банку з IBAN, тип об'єкта з EIC, область з КАТОТТГ. Ставиться в проєкти на .NET 8 і новіших.

Це незалежний навчальний проєкт на відкритих даних. Він не пов'язаний з державними органами, а результат перевірки не є офіційною статистикою чи довідкою з реєстру.

## Встановлення

```
dotnet add package UaCodes
```

Пакет з'явиться на nuget.org після першого релізу. Доти можна склонувати репозиторій і підключити проєкт посиланням:

```
dotnet add reference ../ua-codes/src/UaCodes/UaCodes.csproj
```

## Як користуватися

Усі класи статичні й лежать у просторі імен `UaCodes`. Кожен метод приймає `string?`: на `null`, порожній рядок і будь-що, що не є кодом, повертає `false` або `null` і нічого не кидає. Для методів перевірки є перевантаження з `ReadOnlySpan<char>`, щоб перевіряти шматок рядка без копіювання.

**ЄДРПОУ**

```csharp
Edrpou.IsValid("00100227");    // true
Edrpou.IsValid("00100228");    // false, контрольна цифра не сходиться
Edrpou.Normalize("100227");    // "00100227", нулі, які з'їв Excel, повертаються
```

`IsValid` чекає рівно 8 цифр, тому код, який міг загубити нулі, спершу варто пропустити через `Normalize`.

**РНОКПП**

```csharp
Rnokpp.IsValid("1234567899");  // true, номер синтетичний
```

Дату народження і стать, закладені в номері, бібліотека свідомо не дістає: вона перевіряє коди, а не обробляє персональні дані.

**IBAN**

```csharp
Iban.IsValid("UA21 3223 1300 0002 6007 2335 6600 1");    // true, пробіли й малі літери допускаються
Iban.Normalize("ua21 3223 1300 0002 6007 2335 6600 1");  // "UA213223130000026007233566001"
Iban.BankCode("UA213223130000026007233566001");          // "322313"
```

`Normalize` перевіряє тільки форму, а `BankCode` повертає МФО лише з IBAN, який проходить перевірку контрольного числа.

**EIC**

```csharp
Eic.IsValid("10X1001C--00001X");         // true
Eic.HasValidFormat("62X1580751879965");  // true, форма правильна
Eic.IsValid("62X1580751879965");         // false, контрольний символ не сходиться
Eic.Kind("10X1001C--00001X");            // EicKind.MarketParticipant
```

Тип визначається третім символом: `X` учасник ринку, `Y` область або зона, `Z` точка обліку, `W` ресурс, `T` міждержавна лінія, `V` локація, `A` підстанція.

**КАТОТТГ**

```csharp
Katottg.HasValidFormat("UA74060050020095773");  // true
Katottg.RegionCode("UA74060050020095773");      // "74"
Katottg.RegionName("UA74060050020095773");      // "Чернігівська область"
Katottg.RegionName("UA80000000000093317");      // "місто Київ"
```

У КАТОТТГ немає контрольного розряду, тому `HasValidFormat` перевіряє тільки форму (`UA` і 17 цифр) і те, що перші дві цифри є кодом однієї з 27 одиниць верхнього рівня: 24 областей, Автономної Республіки Крим, Києва і Севастополя.

## Як рахуються контрольні розряди

**ЄДРПОУ.** Перші сім цифр множаться на ваги і додаються, сума ділиться на 11, остача має дорівнювати восьмій цифрі. Ваги 1, 2, 3, 4, 5, 6, 7 для кодів, менших за 30000000 або більших за 60000000, і 7, 1, 2, 3, 4, 5, 6 для решти. Якщо остача 10, суму рахують ще раз із вагами, більшими на 2. Якщо й тоді виходить 10, контрольна цифра 0.

Приклад, `00100227`. Код менший за 30000000, тому ваги звичайні:

```
0·1 + 0·2 + 1·3 + 0·4 + 0·5 + 2·6 + 2·7 = 29
29 mod 11 = 7
```

Остання цифра коду теж 7, код правильний.

**РНОКПП.** Перші дев'ять цифр множаться на ваги -1, 5, 7, 9, 4, 6, 10, 5, 7. Контрольна цифра дорівнює остачі суми від ділення на 11, взятій ще раз за модулем 10. Через від'ємну першу вагу сума може бути від'ємною (у `9000000002` вона дорівнює -9), а оператор `%` у C# тоді повертає від'ємну остачу. Бібліотека зводить її до додатної, інакше такі номери відкидалися б.

**IBAN.** За ISO 13616: перші чотири символи переносяться в кінець, літери замінюються числами (A=10, B=11 ... Z=35), і отримане число ділиться на 97. Остача має бути 1. Число виходить 31-значним, тому остачу рахують по одній цифрі: множать попередню остачу на 10, додають цифру і знову беруть за модулем 97.

Приклад із роз'яснень НБУ, `UA21 3223 1300 0002 6007 2335 6600 1`:

```
UA21 переносимо в кінець:  3223130000026007233566001UA21
U=30, A=10:                3223130000026007233566001301021
остача від ділення на 97:  1
```

Контрольні цифри рахуються так само, тільки замість них ставлять `00`: остача виходить 77, а 98 - 77 = 21.

**EIC.** Кожен символ має числове значення: цифри 0..9, літери A..Z від 10 до 35, дефіс 36. Перші 15 символів множаться на ваги 16, 15 ... 2 і додаються. Контрольне значення дорівнює 36 - (сума - 1) mod 37, і символ із цим значенням має стояти на шістнадцятому місці.

## Чого бібліотека не робить

- Не перевіряє, чи існує код у реєстрі. Правильний контрольний розряд означає лише, що код складено за правилами формату. Чи видано його комусь, знає тільки реєстр.
- Не каже, який код правильний, якщо перевірка не пройшла.
- Не дістає персональні дані з РНОКПП.

## Звідки алгоритми

Перевірки ЄДРПОУ та EIC перенесені з проєкту [energoreestr](https://github.com/maksym-garkusha/energoreestr), де вони прогнані на реєстрах НКРЕКП з data.gov.ua: три набори, 6752 записи у файлах станом на 16.11.2026. Там же видно, як виглядають справжні помилки в кодах: загублені нулі на початку ЄДРПОУ, літера O замість нуля в EIC. Більшість справжніх кодів ЄДРПОУ та EIC у тестах узяті звідти.
